## Things that should not be considered proven

- All PT simulation paths are free of OS socket calls. The PDU object proof supports in-memory paths, but does not yet cover the entire call graph.
- The existence of all flow-chart code means that all algorithms have been restored.
- Replay GUI means complete time-travel state.
- QWaitCondition/QSemaphore itself proves the number and order of thread work.
- Timer registry proves PT has the same retransmission bug as the prototype.
- High entropy alone proves a particular cipher.
- XML ​​reading proves writer, round-trip, or interoperability across versions.

## Continuation of verification

The new checks support heap patterns on PT-04, log limit dialogs on PT-05, as well as RIB/ICMP paths on PT-06. The RB-tree registry, sequence comparator, and lifecycle worker still have original report status for parts that were not re-audited. [Comparison runbook](comparison-tests.md) sets assertions as well as GUI input access limits before execution of the equivalent corpus.

For a new claim, save the artifact identity, observation type (static/runtime), scenario input, output, and test limits. Match protocol behavior to specifications and benchmark implementations. Separate logic simulator testing from vendor hardware or firmware testing.
