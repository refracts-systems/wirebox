# Phase 3 — Versi paket, C ABI, dan cara membuktikan hasil

**Yang dikerjakan.** [Network.store](../../../kernel/src/network.zig) membuat salinan immutable hingga 1600 byte per versi. `packet_id` menyatakan datagram/frame logis; `version_id` menyatakan snapshot byte; `parent_version` menghubungkan encapsulation, decapsulation, atau mutasi. Reply dan ICMP error memperoleh packet ID baru dengan parent yang menunjuk paket pemicu. Setiap `Tx` punya ID sendiri karena satu byte versi dapat dikirim ke beberapa port saat flooding.

Pada [S01](../../evidence/phase-3/byte-walkthrough.md), versi 5 dan 6 sama-sama `packet_id=1`: request sebelum dan sesudah TTL berubah. Versi 9 menambahkan header Ethernet untuk hop R1→PC2, masih packet ID 1. PC2 membuat echo reply dengan packet ID lain. Ini menjawab pertanyaan “byte mana berubah?” serta “apakah ini paket yang sama atau balasan baru?” tanpa menebak dari urutan log.

**Keputusan trace.** Domain trace mencatat keputusan yang mungkin tidak mengubah byte: route terpilih, cache hit/miss, buffering, flood, drop, timeout. Row mempunyai `ordinal`, `event_id`, `cause_id`, entity, version/prior, dan transmission. Scheduler queue tetap berisi pekerjaan mendatang; trace adalah peristiwa/keputusan yang sudah terjadi. Jurnal memakai ring dengan retensi 0–1024 dan menghitung row yang terbuang. Semua versi byte disimpan sampai batas kapasitas; mereka tidak ikut ditimpa oleh kebijakan retensi trace.

**Keputusan ABI.** [wirebox_net.h](../../../kernel/include/wirebox_net.h) memuat `wb_net_*`; [net_abi.zig](../../../kernel/src/net_abi.zig) memegang alokasi dan validasi handle; [network.rs](../../../crates/wirebox-kernel/src/network.rs) mengembalikan `Vec`/struct milik Rust. `Network` Rust thread-bound, mutex menserialisasi call, dan `close`/Drop meminta Zig membebaskan alokasinya. Output packet/trace/field disalin agar UI nanti tidak menyimpan pointer Zig yang dapat invalid. `failed=1` menandai kegagalan engine/resource dan membuat outcome sebelumnya tidak dipercaya; input paket invalid memiliki outcome/trace sendiri tanpa berarti engine crash.

**Bagaimana acceptance menghindari sukses palsu.** [packet_demo.rs](../../../crates/wirebox-headless/src/packet_demo.rs) membangun topologi dari [fixture beku](../../../fixtures/scenarios/icmp-static-v1.json), menjalankan enam kasus, lalu mengecek byte/trace yang benar-benar diterima. Ia membandingkan header forwarding dengan [golden sebelum/sesudah](../../../fixtures/packets/ipv4-forwarding-v1.json); checksum, field bit, ICMP quote, MAC rewrite, dan waktu link diperiksa oleh kode Rust terpisah. S02/S03 wajib menunjukkan ICMP error delivered ke PC1. S04 wajib tiga request ARP dan timeout. S05 wajib reason truncated_ipv4 tanpa event kirim.

Run batch, budget satu event, repeat, serta retensi jurnal 0/1/16 dibandingkan terhadap baseline; total 36 run untuk enam kasus. Ada 37 input negatif melalui ABI, ditambah tes Zig untuk flooding, LPM, payload ganjil, suppression ICMP, dan kegagalan kapasitas. [Bukti G3](../../evidence/phase-3/README.md) menyimpan output dan command. Pembandingan ini adalah determinisme dari initial state; belum ada restore checkpoint atau pembanding capture Linux.

**Latihan membaca satu row.** Pada [S01.json](../../evidence/phase-3/S01.json), cari trace `decrement_ttl` di entity R1. `prior=5`, `version=6`, `detail_a=64`, `detail_b=63`. Buka `packets` versi 5/6 dan periksa offset 8 dan 10–11, lalu cari frame versi 9 dan transmisi 9. Cocokkan `arrival_ns` dengan row `frame_rx` yang mempunyai ID transmisi sama. Dengan begitu keputusan, byte, dan waktu saling mengunci; jumlah row trace tetap bukan jumlah event scheduler.
